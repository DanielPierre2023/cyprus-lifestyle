# i18n engineering notes (increments 5.1 and 5.2, no translation API spend)

## Gates and reports
- `npm run check:i18n` messages parity (existing). `npm run check:i18n-dicts` inline TS dictionaries: fails on any NEW or WORSE gap vs `scripts/i18n-dicts-baseline.json` (admin code exempt). `npm run report:i18n` prints the coverage tables (messages, dictionaries, knowledge base). Both gates run in `npm run ci`.
- An overlay dictionary that omits `en` but has the other six is complete (English lives in `qa.ts`).

## Formatting helper: `lib/i18n/format.ts`
Currency, numbers, dates (Asia/Nicosia), plurals (CLDR: ar zero..many, ru/pl few/many), lists. **Arabic uses Latin digits** (`ar-u-ca-gregory-nu-latn`): ar.json has 0 Arabic-Indic digits, prices and phones are Latin everywhere. Flip `ARABIC_NUMERALS` to `'arab'` to reverse.
Adopt in new code. Call sites that build their own Intl options use the adapters `dateFormatter`, `formatDateWith`, `numberFormatter` (increment 5.2). **English stays byte-identical** at the migrated sites: the adapters use `siteIntlTag()`, where English is the bare `en` the pages always used (US month-day order, "Oct 5"), not the en-GB of `formatDate`. Set `LEGACY_EN_TAG = 'en-GB'` (one line) to move English onto the Cyprus day-month convention everywhere. Migrated in 5.2: agenda, agenda/[slug], account, account/business, article (both ternaries), best/[slug], directory/[type]/[slug], directory/g/[group], luxury, when-to-visit, Header, AdvertiseFunnel, BusinessMap, DirectoryMap, DirectoryReviews, MapExplorer, lib/booking/mail.ts, lib/gyg.ts (el to el-GR, ro to ro-RO; ar stays en-US because GetYourGuide Arabic support could not be verified). **Left for the concierge owner:** `app/api/concierge/proactive/route.ts` (three `toLocale*String(locale)` calls), `lib/concierge/brain.ts:796` (`en-US` money: use `formatCurrency`), `lib/concierge/sources.ts:407` (`Intl.DateTimeFormat`), `components/ConciergeChat.tsx` (`SPEECH_LANG` maps `ar` to `ar-SA`: that is a speech-recognition tag, not a formatter). `lib/map/hours.ts`, `lib/booking/sla.ts` (`en-GB`, tz-specific) and `lib/directory/enrichment-guide.ts` (admin, `en`) are fine.

## Locale resolution and API error codes
`lib/i18n/resolveLocale.ts` (explicit > Referer path > Accept-Language > en). `lib/i18n/apiErrors.ts`: `{ ok:false, code, error }`, additive; English text unchanged. Applied (5.1) to `api/directory/claim` and `api/directory/owner/request`; (5.2) to advertise/lead, advertise/checkout, contact, comments, directory/lead, directory/reviews, newsletter/subscribe, privacy/request, membership/{checkout,restore,status}, account/{forget,portal,logout}, directory/claim/verify (OTP). Three body shapes: `errorBody(code, locale)` (localised `error`), `keyedErrorBody(code, key, locale)` for routes whose clients switch on a short key in `error` ('busy', 'expired'...): `error` is unchanged and `code` + a localised `message` are added, and `codedError(code, text)` where the English text is dynamic (a database message). Not covered: `api/concierge/*` (other owner), `api/partner/claim`, admin. Claim, owner-link and OTP messages: `claimMessages()` in `lib/i18n/notices.ts`.

## Localised transactional pieces
Claim verify e-mail + pages, owner management e-mail + pages (`lib/directory/ownerCopy.ts`), newsletter confirm page (`lib/i18n/notices.ts`). Links carry `lang`/`l` so the pages match the e-mail edition.

**DSAR acknowledgement (wired in 5.2, owner-approved).** `app/api/privacy/request` stores the request, notifies the privacy desk and then e-mails an acknowledgement to the typed address, built in `lib/privacy/ack.ts`. Anti-abuse: (1) at most ONE ack per address per 24 h, decided from `dsar_requests` rows of the last 24 h (authoritative; a failed lookup means no ack) plus `rateLimitKey(email,'privacy-ack',1,86400)` and a global cap of 60 acks per hour; (2) fixed localised template: nothing the visitor typed is echoed, only the reference `DSAR-XXXXXXXX` derived from our own row id; (3) no links, all values HTML-escaped, single-line subject; (4) failure never affects the request (best-effort), the per-IP limit of 6 per minute remains. The ack is HTML only (`sendEmail` has no text part).

## SEO and missing translations: SHOW ALL PAGES (owner decision 2026-10-05)
Every page is served in every edition. Where a DB column is empty (or whitespace) the English text is shown (`pick()`/`pickList()` in `lib/queries.ts`; knowledge-base accessors fall back to `qa.ts`). Pages are NOT noindexed and NOT excluded from the sitemap; every page canonicalises to itself and lists all seven editions plus `x-default` in hreflang (`alternatesFor`). `lib/seo/translationGate.ts` is therefore deliberately NOT wired; it stays available (and tested) should the decision be reversed. Known trade-off: a fallback page repeats English text under a non-English URL (duplicate-content risk); mitigated only by the self-canonical. A possible future refinement is `lang="en"` on fallback blocks for accessibility.
