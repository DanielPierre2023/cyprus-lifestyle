# i18n engineering notes (increment 5.1, no translation spend)

## Gates and reports
- `npm run check:i18n` messages parity (existing). `npm run check:i18n-dicts` inline TS dictionaries: fails on any NEW or WORSE gap vs `scripts/i18n-dicts-baseline.json` (admin code exempt). `npm run report:i18n` prints the coverage tables (messages, dictionaries, knowledge base). Both gates run in `npm run ci`.
- An overlay dictionary that omits `en` but has the other six is complete (English lives in `qa.ts`).

## Formatting helper: `lib/i18n/format.ts`
Currency, numbers, dates (Asia/Nicosia), plurals (CLDR: ar zero..many, ru/pl few/many), lists. **Arabic uses Latin digits** (`ar-u-ca-gregory-nu-latn`): ar.json has 0 Arabic-Indic digits, prices and phones are Latin everywhere. Flip `ARABIC_NUMERALS` to `'arab'` to reverse.
Adopt in new code. Existing call sites that should adopt it (not edited): `agenda/page.tsx`, `agenda/[slug]/page.tsx`, `account/page.tsx`, `article/[slug]/page.tsx` (the `l === 'ar' ? 'ar' : l` ternaries), `best/[slug]`, `directory/[type]/[slug]`, `directory/g/[group]`, `luxury`, `when-to-visit`, `components/{AdvertiseFunnel,BusinessMap,DirectoryMap,DirectoryReviews,Header,MapExplorer}.tsx`, `api/concierge/proactive`, `lib/concierge/brain.ts` (`en-US` money), `lib/gyg.ts` (el/ro/ar mapped to `en-US`), `lib/directory/enrichment-guide.ts`. `lib/map/hours.ts` (`en-GB`, tz-specific) is fine.
